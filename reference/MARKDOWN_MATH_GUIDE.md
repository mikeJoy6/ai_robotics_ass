# 规范：在 Markdown 里写数学公式，使其在 GitLab 和 VSCode 预览中都能渲染

<!-- 读者是 AI agent。英文版：MARKDOWN_MATH_GUIDE_EN.md（内容等价，改一份必须同步另一份）。 -->

## 适用范围

写或改本仓库任何含公式的 `.md` 文件时，必须遵守本文。目标渲染器只有两个：

| 渲染器 | 数学引擎 | 认的定界符 |
|---|---|---|
| GitLab（网页） | KaTeX | `$...$`、`$$...$$`、`` $`...`$ ``、` ```math ` 代码块 |
| VSCode 内置 Markdown 预览 | KaTeX（markdown-it-katex） | `$...$`、`$$...$$` |

两者交集 = **只用 `$...$` 和 `$$...$$`**。其它写法至少在其中一个里显示成原文。

正确样例：`reference/CapturePointSteppingDesign.md`（通过 `check_md_math.py`，0 error 0 warn）。
错误样例：`reference/第一课教案_欧拉角的导数为什么不是角速度.md`（全文用 `\(...\)` 和 `\[...\]`，VSCode 不渲染）。

---

## 规则

### R1 行内公式：`$...$`

```markdown
重心高度 $h$ 决定 $\omega=\sqrt{g/h}$。
```

- 开头 `$` 后、结尾 `$` 前不能有空格。`$ \theta$`、`$\theta $` 在 VSCode 中不渲染。
- 结尾 `$` 后不能紧跟数字（`$x$5` 不渲染）。中间加空格或标点。
- 行内公式只放短表达式。超过约 40 个字符或含 `\frac` 嵌套、矩阵的，改成块公式。

### R2 块公式：`$$` 各占一行

```markdown
前文段落。

$$
\ddot\theta=\omega^2\theta
$$

后文段落。
```

- 开头 `$$` 与结尾 `$$` 各自独占一行，行首不缩进（缩进 4 格会变成代码块）。
- `$$` 块前后各空一行。
- **块内不能有空行。** 部分渲染器在空行处截断公式，后半段显示成原文。需要视觉分隔用 `\\[4pt]` 或拆成两个块。
- 不要把块公式放进列表项、表格、引用块（`>`）内。放在顶层，列表前后断开。
- 不要写 `文字 $$x$$ 文字` 这种行内 `$$`。

### R3 多行公式

推荐用环境包起来：

```markdown
$$
\begin{aligned}
x_{cp} &= x+\frac{\dot x}{\omega} \\
       &= 2Ae^{\omega t}
\end{aligned}
$$
```

| 用途 | 环境 |
|---|---|
| 按 `=` 对齐的推导 | `aligned` |
| 居中、不对齐的多行 | `gathered` |
| 分段 / 联立方程 | `cases` |
| 矩阵 | `bmatrix`、`pmatrix` |

块内顶层直接写 `\\` 换行（不包环境）在 KaTeX 里也能渲染，正确样例里有这种写法，可以保留；新写时优先用环境。

### R4 只用 KaTeX 支持的命令

两个渲染器都是 KaTeX，不是 MathJax，不是 LaTeX。不确定的命令查 <https://katex.org/docs/supported.html>。

| 禁用 | 原因 | 替代 |
|---|---|---|
| `\label` `\ref` `\eqref` | 无交叉引用 | 用文字："见 §2 的式子" |
| `\begin{equation}` / `\begin{align}`（不在 `$$` 里） | 无定界符，不渲染 | `$$` + `aligned` |
| `\newcommand` 跨块使用 | 每个块独立，定义不共享 | 直接写全 |
| `\usepackage` `\require{...}` `\DeclareMathOperator` | LaTeX / MathJax 专有 | `\operatorname{name}` |
| `\bm` | KaTeX 无此命令 | `\boldsymbol` 或 `\mathbf` |
| 自定义宏（如 `\J`） | 未定义，报红 | 写全，例如 `J` 或 `\mathbf J` |

### R5 公式内只用 ASCII

- 公式内不写中文、全角标点（`，` `；` `（）`）。中文说明放在公式外面的段落里。
- 必须在公式里写文字时用 `\text{...}`，内容只用英文。
- 希腊字母写命令 `\theta`，不要直接打 Unicode `θ`。

### R6 和 Markdown 语法冲突的字符

| 场景 | 问题 | 写法 |
|---|---|---|
| 表格单元格里的公式含 `\|` | 被当作表格分隔符，表格错位 | 绝对值 `\lvert x\rvert`，范数 `\lVert x\rVert`，条件 `\mid` |
| 正文里的货币符号 | 两个 `$` 之间被当成公式 | 写 `\$` 或 "USD" / "元" |
| 行内公式在 GitLab 中被 `_` `*` 吃成斜体 | Markdown 先于数学解析 | 先尝试改写；仍不行才用 `` $`...`$ ``（仅 GitLab/GitHub 生效，VSCode 显示为带 `$` 的代码） |
| 标题行里放公式 | 锚点链接变乱码 | 标题只用文字，公式放正文 |

### R7 禁止的定界符（会在 VSCode 显示原文）

~~~text
\( ... \)            行内，LaTeX/ChatGPT 风格        → 改成 $...$
\[ ... \]            块，LaTeX/ChatGPT 风格          → 改成 $$ 各占一行
\begin{equation}...  没有 $$ 包裹                     → 改成 $$ + aligned
```math 代码块        VSCode 内置预览不渲染            → 改成 $$
<sup> <sub> HTML     不是公式，不能复制进代码         → 改成 $x^2$ / $x_i$
公式截图 (png)        不可搜索、不可 diff              → 改成 $$
~~~

## 程序员文档的写法习惯（不是论文，不是教案）

本仓库的读者是写代码的人和 AI。公式文档按下面方式写，不按教科书或讲稿方式写。

| 做 | 不做 |
|---|---|
| 公式里的符号和代码变量一一对应，并用表格列出：符号、代码名、单位、来源文件 | 只写数学符号，读者不知道对应哪个变量 |
| 在推导结尾给出能直接抄进代码的形式，放在代码块里：`omega = sqrt(g / h)` | 只给 LaTeX，实现者自己翻译 |
| 用真实数值代入一次（带单位），并注明数据来源（URDF 文件、yaml、日志） | 只有符号推导，没有数量级 |
| 数值表格：`量 \| 值 \| 来源` | 把数值散落在段落里 |
| 小节标题用编号 + 简短名词：`## 3. horizontal position dynamics` | 标题是问句或口语句子 |
| 用 `§2`、文件路径、`file.cpp:123` 引用 | `\eqref{eq:3}`、"如上式(3.2)所示" |
| 一个块公式只表达一步或一组联立式 | 一个块里塞完整页推导 |
| 直接陈述结论；用 `\boxed{}` 标出最终要实现的式子 | 讲稿结构（"同学们注意"、"视频第几秒"、"板书设计"） |
| 简体中文或英文，全文统一 | 中英混杂的句子 |

## 把错误文件转成正确格式（机械步骤）

处理 `\(...\)` / `\[...\]` 风格的文件：

1. `\(` 和 `\)` 替换为 `$`；去掉紧贴 `$` 内侧的空格。
2. 每个 `\[` 替换为独占一行的 `$$`，每个 `\]` 同样；`$$` 行去掉行首缩进。
3. 块公式如果在列表项里：把它移出列表，放在顶层，前后空行。
4. 删除 `$$` 块内的空行。
5. 处理表格内公式里的 `|`（R6）。
6. 替换 KaTeX 不支持的命令（R4）。
7. 运行 `python3 reference/check_md_math.py <文件>`，必须 `0 error(s)`。
8. 在 VSCode 中打开预览（`Ctrl+Shift+V`）人工抽查，或告诉用户需要抽查的位置。

不要用一条 `sed` 全文替换后就结束：`\[` 可能出现在 `\\[4pt]` 中，第 2 步替换前先 `grep -nF '\\['` 确认。

## 检查脚本

写完或改完任何含公式的 `.md`，必须运行：

```bash
python3 reference/check_md_math.py <文件.md>
```

- 输出 `0 error(s)` 才算完成。`ERROR` 必须修；`WARN` 尽量修，修不了在回复里说明原因。
- 脚本只做静态检查，不能证明一定渲染正确；交付时告诉用户在 VSCode 预览（`Ctrl+Shift+V`）中抽查哪几处复杂公式。

## 最小模板

````markdown
# <主题>

## 关键数值

| 量 | 值 | 来源 |
|---|---|---|
| 质量 $m$ | 69.0 kg | URDF 各 link 质量之和 |
| 重心高度 $h$ | 0.761 m | `stand_target.yaml` 姿态下计算 |

## 1. <步骤名>

重心水平位移近似为 $x \approx h\theta$。由此

$$
\begin{aligned}
I\ddot\theta &= mgh\theta \\
\ddot\theta  &= \omega^2\theta, \qquad \omega=\sqrt{g/h}
\end{aligned}
$$

## 实现

$$
\boxed{x_{cp}=x+\frac{\dot x}{\omega}}
$$

```python
omega = math.sqrt(G / com_height)    # rad/s
x_cp = com_x + com_vx / omega        # m
```
````
